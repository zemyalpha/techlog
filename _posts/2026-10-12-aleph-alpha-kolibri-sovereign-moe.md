# 활성 파라미터 3.5B로 AIME 96점 — 독일 Aleph Alpha 'Kolibri'와 유럽 주권 AI의 실체

2026년 10월 3일, 독일 통일의 날에 맞춰 하이델베르크의 AI 스타트업 Aleph Alpha가 자사의 새 모델 **Kolibri** 전체 가중치를 공개했다. 라이선스는 Apache 2.0, 저장소는 Hugging Face의 `Aleph-Alpha/Kolibri-1`이다. 발표 날짜부터가 의도적이다. 이 모델은 리더보드 등수가 아니라 "유럽이 자기 인프라에서 돌릴 수 있는 AI"라는 메시지를 위해 설계됐다.

이 글에서는 Kolibri의 아키텍처가 왜 그렇게 설계됐는지, 벤치마크 숫자를 어떻게 정직하게 읽어야 하는지, 그리고 실제로 셀프호스팅하려면 무엇이 필요한지를 다룬다. 중국산 오픈 모델(Qwen, GLM, DeepSeek)이 오픈웨이트 시장의 대부분을 차지한 상황에서, 서방 진영의 대안이 어느 수준까지 와 있는지 확인하는 기준점으로도 유용하다.

## 78B 중 3.46B만 쓰는 극단적 MoE

Kolibri의 스펙을 먼저 정리하면 다음과 같다.

| 항목 | 값 |
|---|---|
| 총 파라미터 | 78.1B |
| 토큰당 활성 파라미터 | 3.46B (전체의 4.4%) |
| 레이어 | 50 (전부 MoE, 공유 전문가 1개) |
| 전문가 수 | 384개 중 토큰당 6개 활성 |
| 어텐션 | 슬라이딩 윈도우(512) + 5레이어마다 전체 어텐션 |
| 컨텍스트 | 256k 학습, 서빙 플래그로 최대 1M |
| 라이선스 | Apache 2.0 (FP8 / BF16 가중치 공개) |

핵심은 **4.4%라는 활성 비율**이다. 같은 세대의 오픈 MoE 모델들과 비교해도 공격적인 수치다. 이 극단적인 희소성은 단순히 "작게 만들자"가 아니라 서빙 비용 계산에서 나온 결정이다.

Aleph Alpha는 기술 보고서와 발표문에서 흥미로운 트레이드오프 수치를 공개했다. 내부 실험에서 123B 규모 모델은 H100 2장에서 256k 토큰 롱컨텍스트 쿼리를 **동시에 3개**만 처리할 수 있었지만, 78B 모델은 **18개**를 처리했고 디코딩도 28% 빨랐다는 것. 물론 벤더 자체 측정값이지만, "총 파라미터는 늘리고 활성은 억제한다"는 최근 MoE 설계 트렌드(Qwen3-Next, Nemotron 3 등)와 정확히 같은 방향이라는 점에서 신빙성이 있다.

학습 파이프라인도 눈여겨볼 만하다. Aleph Alpha는 "Model Factory"라는 파이프라인-as-code 방식으로 2026년 1월부터 작업해, 6월 11일에 프로토타입인 Kolibri Origin(30.6B, 컨텍스트 65k, 7.5T 토큰)의 사전학습을 끝냈고, 9월 11일에 Kolibri(78B, 256k, 사전학습 20T 토큰)를 완성했다. 3개월 만에 총 파라미터 2.5배, 컨텍스트 16배, 학습 토큰 2.7배를 끌어올린 셈이다. 제3자 분석에 따르면 사전학습에는 B200 GPU 768개를 21일간 사용했고, 사전학습·미드트레이닝·롱컨텍스트 확장을 합친 총 학습 토큰은 24T에 이른다. 독일어 데이터가 전체의 21.3%를 차지하도록 자체 파이프라인으로 웹 큐레이션 + 합성 데이터 2T 토큰 이상을 추가했다는 점도, "주권 모델"이라는 이름에 걸맞은 부분이다.

## 벤치마크, 정직하게 읽기

Kolibri 발표에서 가장 자주 인용되는 숫자는 **AIME 2025 96.9점**이다. 비교 대상 공개 모델의 벤더 측정치는 Qwen3.6-35B-A3B가 84.6, NVIDIA Nemotron 3 Super 120B-A12B가 91.7, Mistral Small 4가 79.8이다. GPQA Diamond(84.3)와 LiveCodeBench v6(85.9)에서도 비교군을 앞선다.

그러나 여기서 멈추면 안 된다. 이 표는 **전부 Aleph Alpha 자체 평가 하네스**로 돌린 수치다. 경쟁 모델 제작사가 검증한 게 아니라는 뜻이고, 실제로 약점도 그 표 안에 드러나 있다:

- **SWE-Bench Verified 66.4점** — Aleph Alpha의 큰 표에서 이 항목의 경쟁 모델 값은 아예 비어 있다. 제3자 분석 중에는 Qwen3.6-35B가 이 벤치마크에서 73.8점으로 Kolibri를 앞선다고 정리한 것도 있다.
- **BFCL v4(툴 콜) 61.4점** — Qwen3.6의 67.2보다 낮다.
- τ²-bench telecom도 94.7 vs 99.1로 Qwen3.6이 앞선다.

즉 Kolibri는 수학·경쟁 코딩·지식추론에서 강하고, 실제 소프트웨어 엔지니어링 태스크와 복잡한 툴 콜에서는 앞선 오픈 모델이 존재한다. Aleph Alpha 스스로도 "최강"이 아니라 **"품질 대 서빙 비용의 파레토 프론티어"**에 있다고 주장하는데, 이는 비용 효율 주장이지 최고 점수 주장이 아니다. 발표문의 큰 비교표에 Qwen3.8 27B 같은 모델이 종합 점수에서 Kolibri를 앞서는 것으로 나온다는 점도 회사 측은 숨기지 않았다.

참고로 같은 주에 서방 진영 오픈 모델의 또 다른 신호가 있었다. Reflection AI가 10월 5일에 공개한 **Beam**은 총 501B / 활성 23B의 MoE로, 보도에 따르면 SWE-Bench Verified 80.9점을 기록했고 전체 가중치를 Apache 2.0으로 공개할 예정이다. 3.5B 활성의 Kolibri와 23B 활성의 Beam은 목표가 다른 모델이지만, "서방 오픈웨이트 대안"이라는 지형에서는 같은 부류로 묶인다.

## 직접 호스팅해보기: vLLM 설정

Kolibri는 FP8 가중치 기준 약 73.5GiB다. 가중치를 스트리밍해야 하는 만큼 필요한 GPU 메모리는 상당하다. NVIDIA 개발자 포럼에 DGX Spark(GB10)에서 돌린 사용자 사례가 공유돼 있는데, 참고용으로 요약하면:

- 공식 컨테이너는 `ghcr.io/aleph-alpha/aleph-alpha-inference`이고 vLLM 0.29을 요구한다 (Aleph Alpha의 vLLM 플러그인 필요)
- 2048 토큰 프롬프트 / 128 토큰 생성 기준 디코드 속도는 약 20 tok/s, 32k 컨텍스트에서도 프리필 1,131 tok/s를 유지했다 (단일 사용자 실측이므로 절대적 수치로 받아들이면 안 된다)
- 기본적으로 추론(reasoning) 모드가 켜져 있어 중간 턴이 9.6초 정도 걸리므로, 챗 용도라면 reasoning effort를 `none` 또는 `low`로 낮추는 게 좋다

vLLM 실행 예시는 다음과 같다:

```bash
docker run --gpus all --ipc host \
  -v ~/.cache/huggingface:/root/.cache/huggingface \
  -p 8000:8000 \
  --env PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True \
  ghcr.io/aleph-alpha/aleph-alpha-inference \
  --model Aleph-Alpha/Kolibri-1 \
  --gpu-memory-utilization 0.85 \
  --max-model-len 262144 \
  --kv-cache-dtype fp8 \
  --enable-prefix-caching \
  --tool-call-parser kolibri1 \
  --reasoning-parser kolibri1 \
  --enable-auto-tool-choice
```

262,144 토큰을 넘겨서 1M 컨텍스트로 쓰려면 플래그를 추가해야 한다:

```bash
--max-model-len 1048576 \
--hf-overrides '{"max_position_embeddings": 1048576}'
```

추천 샘플링 파라미터는 `temperature=1.0`, `top_p=0.97`, `top_k=128`이며, reasoning effort는 요청마다 none / low / medium / high 4단계로 지정할 수 있다. 토큰당 계산량이 적은 대신 가중치가 큰 모델 특성상, 처리량(latency)보다 동시성과 롱컨텍스트 처리가 강점인 모델임을 감안해 용도를 잡는 것이 좋다.

## 주권 AI라는 프레임의 의미

Kolibri의 진짜 차별점은 숫자가 아니라 **통제 가능성**이다. 데이터 큐레이션, 아키텍처, 학습 인프라, 포스트트레이닝, 평가까지 전 과정을 Aleph Alpha가 다 소유하고 문서화했다는 것. 유럽 연합의 AI 규제 환경에서 공공행정·산업·항공우주 같은 규제 대상 도메인에 AI를 도입하려면 "모델이 어디서 왔는지, 어떤 데이터로 학습됐는지"를 증명해야 하는 경우가 많은데, 이 요구사항에 정확히 조준한 설계다.

한국 독자의 관점에서 보면 이것은 남의 나라 얘기가 아니다. 한국어 특화 오픈웨이트 모델의 부재, 미국 API 의존도, 데이터 주권 논쟁 — Aleph Alpha가 푸는 문제와 구조적으로 같은 문제다. 독일어 2T 토큰을 자체 파이프라인으로 큐레이션해 3개월 만에 리소닝 모델을 완성한 과정은, 저자원 언어권에서 "주권 모델"을 만드는 비용과 기간이 과거의 상식보다 훨씬 낮아졌다는 신호로 읽을 수 있다.

## 핵심 요약

- **Kolibri는 78.1B 총 파라미터 / 3.46B 활성(4.4%)의 영어-독일어 MoE**로, 2026년 10월 3일 Apache 2.0 전체 가중치 공개. 컨텍스트는 256k 학습 / 1M 서빙
- AIME 96.9, GPQA Diamond 84.3, LiveCodeBench v6 85.9 등 벤더 자체 측정으로 강세. 단 SWE-Bench Verified 66.4, 툴 콜 벤치마크에서는 Qwen3.6 등이 앞선다 — 벤치마크는 전부 Aleph Alpha 자체 평가라는 점을 감안해야 한다
- 4.4% 활성 비율은 H100 2장에서 256k 쿼리 동시처리 3건 → 18건이라는 벤더 측정치로 이어지는 서빙 비용 최적화 설계다
- 호스팅에는 vLLM 0.29 + 전용 플러그인이 필요하고 FP8 가중치 73.5GiB를 감안한 GPU 메모리 계획이 필수다
- 규제 도메인과 데이터 주권이 필요한 조직에게는 실제로 선택지가 되는 모델이고, 저자원 언어권 오픈 모델 전략의 좋은 참고 사례다

당장 해볼 수 있는 첫 단계는 Hugging Face에서 FP8 가중치를 내려받아 위의 vLLM 컨테이너를 띄워보는 것이다. 256k 컨텍스트 문서 요약 같은 워크로드에 reasoning effort를 조절해가며 토큰당 비용을 직접 측정해보면, "파레토 프론티어"라는 주장이 마케팅인지 실재인지 스스로 판단할 수 있다.
