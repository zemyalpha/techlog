# 프론티어 MoE가 맥 스튜디오에 들어온 2026년 9월 — GLM-5.3-Flash와 Qwen3.8-Flash-Next를 로컬로 돌리는 법과 라이선스 함정

"프론티어 모델은 서버 없이는 못 돌린다"는 말은 2026년 여름까지 사실이었다. 9월 들어 상황이 바뀌었다. 지푸(Zhipu)의 GLM-5.3-Flash와 알리바바의 Qwen3.8-Flash-Next라는 두 개의 프론티어급 MoE(전문가 혼합) 모델이 양자화 형태로 128GB 맥에서 돌아가는 크기로 출시됐다. 둘 다 총 파라미터는 100B를 훌쩍 넘지만, 토큰당 활성 파라미터는 각각 18B와 6B에 불과하다. 이 차이가 로컬 실행을 가능하게 만드는 핵심이다.

이 글은 두 모델을 실제로 맥에서 돌리려는 사람을 위한 실전 가이드다. 얼마나 큰 메모리가 필요한지, 어떤 런타임을 써야 하는지, 그리고 대부분의 리뷰가 간과하는 라이선스 조항 — 특히 Qwen3.8-Flash-Next의 코딩 어시스턴트 carve-out이 왜 문제인지까지 다룬다.

## 왜 지금 MoE인가: 활성 파라미터의 경제학

MoE 모델의 추론 비용은 총 파라미터 수가 아니라 활성 파라미터 수로 결정된다. GLM-5.3-Flash는 320B 중 토큰당 18B, Qwen3.8-Flash-Next는 125B 중 6B만 흐른다. 토큰 하나를 생성할 때 전체 가중치를 스캔하는 게 아니라 라우터가 고른 소수의 전문가만 GPU/메모리 대역폭을 소비하기 때문이다.

여기서 맥 특유의 트레이드오프가 생긴다.

- **메모리 용량(RAM)**: 총 파라미터가 양자화된 크기 전부를 담아야 한다. 320B의 3비트 양자화는 약 120GB.
- **메모리 대역폭**: 생성 속도는 활성 파라미터 크기에 비례한다. 18B 활성 모델은 토큰당 18B어치 가중치만 읽으면 된다.

즉 맥은 "용량은 크지만 대역폭이 상대적으로 느린" 머신이라, 큰 총 파라미터 + 작은 활성 파라미터 조합에 최적이다. NVIDIA의 DGX와 정반대 방향의 설계지만, 이번 두 모델은 정확히 이 전제에 맞춰 나왔다. 특히 Qwen3.8-Flash-Next는 51B 파라미터를 2~3글자 조각(n-gram)으로 인덱싱된 별도 임베딩 테이블로 붙였는데, 개발팀의 설명은 계산보다 메모리가 부족한 가속기로 오프로드하기 쉽게 만들겠다는 것 — TNW는 이를 수출 통제로 최고 성능 칩을 못 사는 중국 랩의 상황이 반영된 설계로 해석했다. 계산이 아니라 대역폭과 용량이 병목인 맥에서도 같은 설계가 그대로 이득이 된다.

## GLM-5.3-Flash: "Ox Alpha"의 정체와 실행 방법

8월 내내 평가 아레나에서 익명 모델 "Ox Alpha"로 돌다가, 지푸가 8월 26일 이것이 GLM-5.3-Flash(320B-A18B)임을 밝히고 MIT 라이선스로 Hugging Face에 웨이트를 공개했다. GLM-5 시리즈 최초의 네이티브 멀티모달 모델이고, 희소 어텐션과 선형 어텐션의 하이브리드로 장문 컨텍스트 서빙 비용을 줄였다고 모델 카드는 밝힌다.

모델 카드에 공개된 벤치마크는 Terminal-Bench 2.1에서 84.3이다(같은 벤치마크에서 Qwen3.8-27B는 73.0을 보고). 단, 이 수치들은 벤더 스캐폴드 기준이므로 표준화된 하니스보다 15~20점 높게 나오는 게 보통이라는 점은 감안해야 한다. 지푸 스스로는 GLM-5.2를 넘어서고 코딩·에이전트 작업에서 Claude Opus 4.8에 근접한다고 주장한다.

로컬 실행은 양자화 티어에 따라 갈린다:

| 양자화 | 크기 | 최소 맥 | 예상 속도(M5 Max/Ultra 기준) |
|---|---|---|---|
| UD-IQ3_XXS (3-bit) | 120GB | 128GB (M5/M4 Max, 빠듯) | ~27 tok/s |
| UD-IQ4_XS | 157GB | 192GB M4 Ultra | ~32 tok/s |
| UD-Q4_K_XL (4-bit) | 200GB | 256GB M5/M3 Ultra | ~35 tok/s |

(크기와 티어는 Unsloth의 동적 GGUF 기준, 속도는 LLMCheck 인덱스의 대역폭 모델 추정치)

실행 방법 — Unsloth GGUF를 llama.cpp로 돌리는 경우:

```bash
# GLM-5.3 지원 브랜치 필요 (2026년 9월 기준, 정식 릴리스에는 아직 미포함)
git clone -b glm5 https://github.com/ggml-org/llama.cpp
cd llama.cpp && cmake -B build && cmake --build build -j

./build/bin/llama-server \
  -hf unsloth/GLM-5.3-Flash-GGUF:UD-IQ3_XXS \
  -c 32768 -ngl 999 \
  --host 127.0.0.1 --port 8080
```

주의점이 두 가지 있다. 첫째, 2026년 9월 시점 GGUF는 GLM-5 인식이 포함된 llama.cpp 브랜치가 필요하다. 정식 릴리스가 나오기 전에는 브랜치 빌드가 필수다. 둘째, 3비트 양자화가 120GB면 128GB 머신에서 컨텍스트를 포함해 남는 여유는 8GB 정도다. 컨텍스트 길이를 길게 잡으면 스왑이 터지니, 128GB 티어에서는 `-c` 값을 보수적으로 잡아야 한다.

MLX 루트는 커뮤니티 변환이 존재하지만 공식 지원은 아니라는 점도 알아두자.

## Qwen3.8-Flash-Next: Qwen4 아키텍처의 예고편

Qwen3.8-Flash-Next는 이름 그대로 다음 세대 Qwen4의 아키텍처 프리뷰다. 125B 중 6B 활성이라는 극단적 희소성 외에 눈에 띄는 구성 요소:

- Gated DeltaNet + Qwen Sparse Attention, 48 레이어
- 512개 전문가 중 토큰당 10개 라우팅 + 1개 공유
- 51B n-gram 임베딩 테이블 + 4B 다중 토큰 예측 헤드
- 네이티브 텍스트·이미지·비디오 입력, 262K 컨텍스트(YaRN으로 1M)

모델 카드 기준 SWE-Bench Pro 62.5(벤더 스캐폴드), LiveCodeBench v6 91.9, GPQA Diamond 91.7로, Qwen3.8-27B보다 각각 소폭 위다.

맥에서 중요한 숫자는 112GB다. 커뮤니티 4비트 MLX 변환의 크기인데, 51B n-gram 테이블이 메모리에 상주하므로 이 모델은 96GB가 아니라 128GB 티어 모델이다. 6B만 활성화되므로 속도는 체감상 쾌적하다 — LLMCheck 추정으로 M5 Max에서 약 49 tok/s, M4 Ultra 78 tok/s, M5 Ultra 85 tok/s.

```bash
# MLX 루트 (128GB+ Apple Silicon)
pip install mlx-lm
mlx_lm.generate \
  --model mlx-community/Qwen3.8-Flash-Next-4bit \
  --prompt "파이썬으로 지수 백오프 재시도를 구현해줘" \
  --max-tokens 1024
```

모델명은 커뮤니티 변환에 따라 다를 수 있으니 Hugging Face에서 `Qwen3.8-Flash-Next MLX`로 검색해 최신 변환을 확인하자.

## 진짜 함정은 라이선스다

성능과 크기보다 더 중요한 차이가 라이선스에 있다.

**GLM-5.3-Flash는 MIT다.** 활용에 제약이 없다. 다음 달 나올 수도, 안 나올 수도 있는 플래그십 GLM-5.3(753B, 활성 ~40B)은 다르다. 웨이트가 8월 25일 공개됐지만 라이선스는 자체적인 "GLM-5.3 License"로, 12개월 총 매출이 100억 달러를 넘는 모델-as-a-service 사업자는 Z.AI의 보안 심사를 통과해야 한다. 대부분의 회사에는 사실상 MIT지만, 글로벌 빅테크에는 게이트가 하나 생긴 셈이다. 지푸가 플래그십과 Flash에 서로 다른 라이선스를 적용한 건 이번이 처음이다.

**Qwen3.8-Flash-Next는 Qwen Community 1.0이다.** Apache 2.0이 아니다. 이 구분이 실무적으로 치명적이다:

1. 로컬 실행, 사내 사용은 무제한이다.
2. 하지만 **모델-as-a-service로 제공하거나, 코딩·오피스 생산성용 "AI 워크 어시스턴트" 제품을 만들려면 알리바바의 별도 상업 라이선스가 필요하다.**
3. 월 1억 사용자 또는 월 2,000만 달러 매출을 넘는 제품은 모델명을 눈에 띄게 표시해야 한다.

2번의 carve-out이 문제다. 로컬 LLM 사용자가 이 모델로 가장 먼저 만들고 싶어 하는 게 바로 코딩 어시스턴트인데, 그 정확한 용도가 별도 라이선스 대상이기 때문이다. TNW는 나아가 이 라이선스가 EU AI Act의 오픈소스 면제(Article 53(2), Recital 103 — 유료/수익화되는 컴포넌트는 면제 대상이 아님)를 받을 수 있을지도 의문이라고 지적했다. 개인 실험용이라면 아무 문제 없지만, 제품에 얹으려면 법무 검토가 선행돼야 한다.

참고로 이번 달 오픈 생태계의 지형 자체가 흔들리는 사건도 있었다. NVIDIA가 9월 3일 Hugging Face를 129억 3천만 달러에 인수하기로 합의했다. 거래는 2027년 상반기 클로즈 예정이다. 두 모델의 웨이트가 올라와 있는 바로 그 플랫폼이 NVIDIA 산하로 들어가는 셈이라, 오픈웨이트 배포 경로의 장기 안정성을 지켜볼 필요가 있다.

## 선택 가이드: 당신의 맥에는 무엇을 올릴 것인가

- **24~48GB (맥북프로 M 시리즈)**: 둘 다 못 올린다. 이 티어에서는 Qwen3.8-27B(4비트 약 19GB, Apache 2.0)가 여전히 최선이다. LLMCheck 인덱스 기준 맥 검증 모델 1위이기도 하다.
- **128GB (M5/M4 Max)**: GLM-5.3-Flash 3비트(120GB)는 올라가지만 컨텍스트 여유가 빠듯하다. Qwen3.8-Flash-Next 4비트 MLX(112GB)가 같은 티어에서는 더 나은 선택 — 6B 활성이라 속도도 훨씬 낫다. 단, 상업 제품 계획이 있다면 라이선스부터 확인하라.
- **192~256GB (Mac Studio)**: 선택의 영역이다. GLM-5.3-Flash 4비트(157~200GB)를 품질 우선으로 올리거나, 여유 메모리로 긴 컨텍스트를 잡거나, 아니면 2비트 양자화(239GB)로 GLM-5.3 플래그십까지 노려볼 수 있다.

## 마무리: 세 가지 기억할 것

- **활성 파라미터가 속도를, 총 파라미터가 메모리를 결정한다.** MoE 시대의 맥 구매 기준은 "내 RAM에 양자화된 총 크기가 들어가는가 + 활성 파라미터가 몇 B인가"로 바뀌었다.
- **벤더 벤치마크는 15~20점 할인해서 읽어라.** 이 글에 인용된 Terminal-Bench, SWE-Bench Pro 수치는 전부 벤더 스캐폴드 기준이다. 모델 카드 수치를 절대값으로 믿고 선택하면 실망한다.
- **라이선스가 성능보다 먼저다.** GLM-5.3-Flash는 MIT, Qwen3.8-Flash-Next는 코딩 어시스턴트 제품화에 별도 상업 라이선스가 필요한 Qwen Community 1.0. 개인 로컬은 자유지만, "이걸로 뭔가 만들어 팔자"라는 순간 조항을 읽어야 한다.

당장 해볼 첫 단계는 128GB 이상의 맥이 있다면 Qwen3.8-Flash-Next 4비트 MLX를, 그보다 작은 머신이라면 Qwen3.8-27B를 올려보는 것이다. 그리고 Hugging Face에서 두 모델의 라이선스 원문을 직접 읽어보라. 이 글의 요약보다 원문이 항상 우선한다.
