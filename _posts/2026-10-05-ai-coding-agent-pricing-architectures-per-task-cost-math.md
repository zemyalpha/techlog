# 같은 $20인데 청구서는 70배 다르다 — AI 코딩 에이전트 4가지 요금 아키텍처와 태스크당 비용 수학

"Claude Code는 월 $20. Cursor도 월 $20. 그런데 Cursor는 나에게 $1,400을 청구했다."

2026년 개발자 커뮤니티에서 널리 공유된 이 하소연은 과장이 아니다. 문제는 요금표의 숫자가 아니라 **요금 아키텍처**다. Claude Code, Cursor, Devin, GitHub Copilot는 모두 $20대 진입 가격을 내걸고 있지만, 초과 시 어떤 일이 벌어지는지는 완전히 다른 규칙으로 움직인다. 이 글에서는 2026년 10월 기준 네 도구의 요금 구조를 "리스크가 누구에게 있는가"라는 관점에서 해부하고, 동일한 작업이 도구마다 얼마나 다른 비용을 만드는지 계산해본다. 마지막으로 구독 요금이 아니라 토큰 흐름 자체를 줄이는 방법을 다룬다.

## 1. 왜 요금 아키텍처가 가격표보다 중요한가

요금제를 비교할 때 대부분의 개발자는 월 요금을 본다. 하지만 실제 지출을 결정하는 것은 세 가지 다른 질문이다.

1. **포함분이 소진되면 무슨 일이 생기는가** — 감속하는가, API 단가로 과금되는가, 그냥 멈추는가
2. **단위가 무엇인가** — 토큰인가, 요청인가, 시간인가, 좌석인가
3. **리스크가 누구에게 있는가** — 벤더가 상한을 보증하는가, 사용자가 사용량을 감시해야 하는가

이 세 질문에 대한 답에 따라 네 도구는 네 가지 서로 다른 아키텍처로 나뉜다. 같은 "함수 리팩터링 한 번"이 도구에 따라 $0.04짜리 작업이 되기도 하고 $2짜리 작업이 되기도 하는 이유가 여기 있다.

## 2. 네 가지 요금 아키텍처 해부

### 2.1 Claude Code — 상한이 있는 플랫 구독 (리스크: 벤더)

Anthropic 공식 가격 페이지 기준 Claude 구독은 Pro 월 $20(연간 결제 시 $17), Max 5x 월 $100, Max 20x 월 $200이다. Claude Code는 별도 요금제가 아니라 이 구독 허용량을 그대로 공유한다. Anthropic 문서화된 세부 규칙에 따르면 사용량 제한은 5시간짜리 세션 윈도우 단위로 리셋되며, 주간 상한도 별도로 존재한다.

이 모델의 핵심 특징은 **초과 요금이 존재하지 않는다**는 것이다. 창을 소진하면 Claude Code가 느려지거나 일시 정지될 뿐, 예고 없이 청구서가 불어나는 일은 없다. 재무 담당자 관점에서 전통적 소프트웨어처럼 월 고정비로 예측이 가능한 유일한 구조다. 대가는 진짜 상한이다. 집중적인 리팩터링 세션이 오후 한 번에 창을 전부 소진할 수 있다.

한 가지 주의할 점. "Max 5x는 5시간당 약 88K 토큰, Max 20x는 약 220K 토큰"이라는 구체적 수치가 제3자 분석에서 인용되곤 하지만, Anthropic 자체가 정확한 토큰 수를 공식 문서로 고정해 공개하지는 않는다. 이 숫자들은 독립 추정치로 읽어야 한다.

### 2.2 Cursor — 달러 크레딧 풀 (리스크: 사용자)

Cursor 공식 가격 페이지 기준 Hobby는 무료, Pro 월 $20, Teams는 사용자당 월 $40부터 시작한다. 2026년 8월 기준 구조를 보면 상위 티어는 Pro+ 월 $60, Ultra 월 $200이며, 여기서 중요한 것은 스티커 가격과 별개로 **서드파티 모델용 달러 허용량**이 붙는다는 점이다. Ultra는 $200 플랜에 $400짜리 서드파티 허용량을 포함한다.

2026년의 Cursor는 사실상 두 개의 풀로 움직인다. 첫째는 Cursor 자체 모델(Grok 4.5, Composer 2.5)을 위한 "관대한 포함 사용량" 풀이고, 둘째는 Anthropic·OpenAI·Google 등 40여 개 서드파티 모델을 위한 달러 단위 풀이다. 탭 완성은 모든 유료 플랜에서 무제한이며 어느 풀에서도 차감되지 않는다.

문제는 풀이 바닥났을 때다. 서드파티 허용량이 소진되면 같은 API 단가로 온디맨드 과금이 이어진다. 프리미엄 모델을 고정(pinning)해놓고 대형 코드베이스 리팩터링을 돌리면 $400 풀이 며칠 만에 사라지고, 그 이후가 바로 "$20 플랜에서 $1,400 청구"가 나오는 지점이다. Cursor 모델의 리스크는 사용자가 사용량을 감시할 때만 작동하는 구조다. 커뮤니티 가이드들이 "가장 큰 절감 레버는 어떤 모델을 핀하느냐다"라고 강조하는 이유가 이것이다.

### 2.3 Devin — ACU 미터제 (리스크: 태스크 스코프)

Cognition의 Devin은 넷 중 가장 투명한 구조다. Agent Compute Unit(ACU) 단위로 과금하며, 1 ACU는 약 15분의 자율 작업에 해당한다. 2026년 기준 Core 플랜은 월 $20 + ACU당 $2.25, Team 플랜은 월 $500에 250 ACU 포함(추가 ACU는 $2.00)이다. 시간으로 환산하면 활성 작업 1시간당 약 $9다. 이 수치는 복수의 독립 가이드가 동일하게 확인한다.

미터제의 장점은 정직함이다. 계획 수립, 브라우저 조작, 코드 실행, 컨텍스트 수집까지 포함해 "에이전트가 실제로 한 일"에 돈을 낸다. 단점은 태스크 스코프가 비용을 직접 결정한다는 것. 모호한 지시를 주면 Devin은 탐색하고 되돌아가고 테스트를 다시 돌리며 그 모든 시간이 ACU로 청구된다. 파일과 스펙을 정확히 지정하면 같은 기능이라도 ACU 소모가 줄어든다. Devin이 2025년에 진입료를 $500에서 $20으로 낮췄지만 ACU 단가는 그대로라는 점도 알아둘 필요가 있다. "시작은 저렴하지만 본격적으로 쓰는 비용은 태스크 복잡도가 결정한다"는 뜻이다.

### 2.4 GitHub Copilot — 시트 + AI Credits (리스크: 혼합)

GitHub 공식 플랜 페이지 기준 Free $0, Pro 월 $10, Pro+ 월 $39, Max 월 $100이다. 과거의 "프리미엄 요청" 개수 체계는 2026년 6월 **GitHub AI Credits** 체계로 전환됐다. 채팅, 에이전트 모드, 코드 리뷰, Copilot CLI, Copilot 앱이 모두 이 크레딧을 소모한다. 기본 크레딧은 플랜에 포함되고(Free는 제한적, Pro $10, Pro+ $39, Max $200 상당), 상한을 넘기고 싶으면 Flex allotment라는 월 추가 요금제(Pro +$5, Pro+ +$31, Max +$100)를 붙일 수 있다. 조직 관점에서는 Max 플랜의 풀링(pooled usage)과 관리자 지출 통제가 특징이다.

이 구조는 전통적 SaaS 시트 라이선스에 가장 가깝지만, 크레딧 소모율이 모델과 기능에 따라 크게 달라진다는 점을 주의해야 한다. 프로젝트 관리자가 모델 믹스를 바꾸지 않고 예산만 세우면 유효 단가가 몇 배로 뛸 수 있다.

## 3. 태스크당 비용 수학

추상적 구조보다 구체적 숫자가 낫다. 공개 요금과 독립 분석을 기준으로 표준 작업의 비용을 계산해보면 다음과 같다. 도구마다 청구 단위가 다르므로 "동일 작업"의 정의에 한계가 있다는 점은 전제로 둔다.

| 작업 | Claude Code (Max) | Cursor (Ultra) | Devin (Core) | Copilot (Pro+) |
|---|---|---|---|---|
| 단순 함수 리팩터링 | 플랜 포함 (유효 수십 센트 이하) | $0.10~0.50 | $0.56+ (15분) | 크레딧 소량 |
| 다중 파일 기능 추가 | 플랜 포함 | $1~3 | $2.25+ (1시간) | 크레딧 다량 |
| 종일 자율 스프린트 | 플랜 포함 (창 소진 시 감속) | $15~50+ 온디맨드 | $36~72 (8 ACU시간) | 플랜 + Flex |
| 초과 시 동작 | 감속/정지, 추가 청구 없음 | API 단가 무제한 과금 | ACU 계속 적립 | Flex 또는 정지 |

표에서 드러나는 결론은 세 가지다.

- **집중형 개발자**에게 Claude Code의 플랫 상한은 보험이다. 최악의 경우도 월 $100~200이다.
- **자율 스프린트를 대량으로 돌리는** 경우 Devin은 시간당 $9로 예측 가능하지만, Cursor 온디맨드는 상한이 없다.
- **팀 단위 조달**에서는 Copilot의 시트+크레딧 구조가 회계 처리에 가장 익숙하다.

간단한 계산기 코드로 자기 상황을 추정해볼 수 있다.

```python
def monthly_cost(tool, tasks_per_day, avg_metric, days=22):
    """tool별 월 비용 추정. avg_metric 단위는 tool마다 다름."""
    plans = {
        "claude_code": lambda: 100,  # Max 5x: 창 내에서는 고정
        "cursor_ultra": lambda: 200 + max(0, tasks_per_day * avg_metric - 400 / days) * days,
        "devin_core": lambda: 20 + tasks_per_day * avg_metric * 2.25 * days,
        "copilot_proplus": lambda: 39 + max(0, tasks_per_day * avg_metric) * days,
    }
    return plans[tool]()

# 하루 3회 에이전트 태스크, 태스크당 평균 지표(시간 또는 초과 크레딧 $) 가정
for t in ["claude_code", "cursor_ultra", "devin_core", "copilot_proplus"]:
    print(t, f"${monthly_cost(t, 3, 1.0):,.0f}/월")
```

이 계산의 목적은 정확한 예측이 아니라 **자기 사용 패턴이 어느 아키텍처의 리스크 영역에 있는지** 파악하는 것이다.

## 4. 요금제를 바꾸기 전에: 토큰이 새는 5곳

도구를 갈아타는 것보다 먼저 할 일이 있다. 어느 도구를 쓰든 결국 비용은 **매 턴 모델을 통과하는 컨텍스트의 양**이 결정하며, 여기에는 몇 가지 체계적인 낭비 지점이 있다. 토큰 최적화 도구를 만드는 Terse의 2026년 분석은 이 낭비를 다섯 곳으로 정리한다.

1. **턴마다 누적되는 컨텍스트** — 에이전트 세션은 매 턴 지금까지의 대화 전체를 다시 보낸다. 5K 토큰으로 시작한 세션이 끝날 무렵에는 턴당 150K+ 토큰을 재전송한다. 캐싱이나 컴팩션이 없다면 이 누적 이력에 반복해서 돈을 낸다.
2. **리포지터리 맵과 파일 컨텍스트** — 에이전트가 코드를 고치려면 코드를 봐야 한다. 압축된 리포 맵을 보내는 도구도 있고 파일 전체를 컨텍스트에 올리는 도구도 있다. 생성 코드, 락파일, 벤더 의존성은 한 번에 수만 토큰을 쏟아낼 수 있다.
3. **중복 파일 읽기** — Terse 분석에 따르면 전형적인 세션의 파일 읽기 약 3분의 1이 중복이다. 에이전트가 이미 읽은 파일을 잊고 3~5번 다시 읽으며, 매번 전체 토큰 수가 재과금된다.
4. **장황한 프롬프트와 CLI 노이즈** — 터미널 에이전트는 파일 목록, 테스트 로그, 스택 트레이스를 그대로 파이프한다. Terse는 하나의 장황한 명령이 10K~150K 토큰의 노이즈를 추가할 수 있다고 추정한다.
5. **프론티어 모델의 출력 단가** — 출력 토큰은 입력보다 4~5배 비싸다. 긴 설명과 파일 전체 재작성을 뱉는 에이전트는 출력 비용이 지배한다. 싼 모델로 충분한 태스크에 최상위 모델을 쓰는 것이 월 청구서에서 가장 큰 배수를 만든다.

이 낭비를 막는 실전 지점은 다음과 같다.

```bash
# 1. 컴팩션: 세션이 컨텍스트의 60~70%에 도달하면 요약 후 리셋
# Claude Code 예: 세션 중간에 실행
/compact  # 대화를 요약해서 컨텍스트를 비운다

# 2. 노이즈 차단: 출력이 큰 명령은 파이프로 자르기
git log --oneline -20        # 전체 로그 대신
ls -1 src/                   # 상세 리스트 대신
```

```python
# 3. 모델 라우팅: 태스크 난이도로 모델 결정 (의사코드)
def pick_model(task):
    if task.type in ("문서 수정", "테스트 추가", "간단한 리팩터"):
        return "cheap_model"    # 플래그십 대비 수 분의 1 비용
    if task.type in ("아키텍처 변경", "디버깅", "다중 파일 설계"):
        return "frontier_model"  # 여기만 비싼 모델
    return "mid_tier"
```

Terse는 이런 압축·중복 제거·캐싱·모델 right-sizing을 통해 토큰 청구를 40~70% 줄일 수 있다고 주장하는데, 이는 자사 도구의 마케팅 수치이므로 그대로 믿기보다 "적용 가능한 원칙의 방향성"으로 받아들이는 게 맞다. 다만 위 다섯 낭비 지점 자체는 어느 도구를 쓰든 구조적으로 성립하는 사실이다.

## 5. 선택 기준 요약

- **예측 가능성이 최우선이라면** (CFO가 월 고정비를 원하는 조직): 상한이 있고 초과 청구가 없는 Claude Code형 플랫 구독.
- **서드파티 프리미엄 모델을 하루 종일 써야 한다면**: Cursor Ultra처럼 큰 크레딧 풀. 단 온디맨드 전환 시점을 반드시 모니터링 알림으로 설정할 것.
- **자율 장기 태스크가 주 업무라면**: Devin의 ACU처럼 시간 기반 미터제가 정직하다. 단 태스크 스코프를 조이는 것이 유일한 비용 레버다.
- **팀 조달·감사가 중요하다면**: Copilot의 시트+AI Credits+Flex 구조가 회계에 가장 잘 붙는다.
